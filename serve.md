# Локальный сервер для теста

Файлы нельзя открывать напрямую как `file://` — модуль-скрипты и доступ к камере требуют HTTP(S)-сервер.

## Вариант 1: Python

```bash
cd F:\Cheharda\AR\webar-postcard; python -m http.server 8000
```

Открой `http://localhost:8000` на компьютере или `http://<IP-компьютера>:8000` с телефона (см. ниже, как узнать IP).

## Вариант 2: Node

```bash
cd F:\Cheharda\AR\webar-postcard; npx serve -l 8000
```

или

```bash
cd F:\Cheharda\AR\webar-postcard; npx http-server -p 8000
```

> В Windows PowerShell 5.1 команды разделяются точкой с запятой `;` — оператор `&&` там не поддерживается и даёт ошибку `Лексема "&&" не является допустимым разделителем операторов`.

### Если порт занят

Ошибка `PermissionError: [WinError 10013]` означает, что порт уже кем-то слушается или зарезервирован системой. Найти виновника:

```bash
Get-NetTCPConnection -LocalPort 8000 -State Listen | Select-Object LocalPort, OwningProcess
```

и по `OwningProcess` посмотреть процесс:

```bash
Get-Process -Id <PID> | Select-Object Id, ProcessName, Path
```

Проще всего не воевать за порт, а взять свободный — 8000, 8081, 5500.

Отдельно: Hyper-V/WSL резервируют целые диапазоны портов, их видно так:

```bash
netsh int ipv4 show excludedportrange protocol=tcp
```

## Как узнать локальный IP компьютера

**Windows:**

```bash
ipconfig
```

Ищи строку `IPv4-адрес` в блоке своего активного адаптера (Wi-Fi или Ethernet), например `192.168.1.42`.

**macOS/Linux:**

```bash
ifconfig
```

Ищи `inet` в блоке `en0` (Wi-Fi) — тот же принцип.

Телефон должен быть в той же Wi-Fi сети, что и компьютер.

## Важно про HTTPS на телефоне

Доступ к камере (`getUserMedia`) браузеры дают только в защищённом контексте: `https://` или `localhost`. Адрес вида `http://192.168.x.x:8000` защищённым контекстом **не считается** — поэтому с телефона по локальному IP камера, скорее всего, не запустится ни в iOS Safari, ни в Android Chrome. Страница откроется, но AR не стартует.

То есть проверка с телефона почти наверняка потребует HTTPS-туннель:

```bash
npx.cmd localtunnel --port 8000
```

или

```bash
npx.cmd ngrok http 8000
```

Оба выдадут временный `https://...` адрес, который можно открыть с телефона откуда угодно (не только по Wi-Fi) — на нём камера заработает.

> **Почему `npx.cmd`, а не `npx`.** В PowerShell вызов `npx` попадает на обёртку `npx.ps1`, и при политике выполнения `Restricted` он падает с ошибкой `Невозможно загрузить файл ... npx.ps1, так как выполнение сценариев отключено в этой системе`. Явный вызов `npx.cmd` идёт мимо `.ps1` и работает без изменения политик безопасности. (Альтернатива — разрешить сценарии через `Set-ExecutionPolicy`, но это правка настроек безопасности системы, и делать её стоит осознанно и самостоятельно.)

> **localtunnel** при первом открытии ссылки показывает страницу-заглушку и просит ввести пароль — это публичный IP-адрес компьютера, на котором запущен туннель (его подскажет сама страница). Разовая формальность, дальше открывается нормально.

> Если на компьютере включён VPN, туннель и доступ по локальной сети могут вести себя непредсказуемо — при проблемах попробуй отключить VPN на время теста.
